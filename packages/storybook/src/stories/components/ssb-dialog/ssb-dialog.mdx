`ssb-dialog` shows a modal window layered over the page. It closes via the ✕ button, a backdrop click or the Escape key and emits `ssbOpenChange`.

## Table of Contents

- [Intent](#intent)
- [Guidelines](#guidelines)
- [Examples](#examples)
- [Properties](#properties)

---

## Intent

Use a dialog to interrupt the flow for a focused task such as editing details or collecting a short form before returning to the page. Do NOT use a dialog for destructive confirmations — use `ssb-alert-dialog` for those — or for passive notifications, which belong in `ssb-toast`.

---

## Guidelines

- **Do** set `dialogTitle` so the dialog has a visible heading and an accessible name.
- **Do** place actions in the `footer` slot with the primary action last.
- **Do** listen to `ssbOpenChange` to keep application state in sync.
- **Don't** nest dialogs inside each other.
- **Don't** set `hideClose` unless the footer offers an explicit way out.
